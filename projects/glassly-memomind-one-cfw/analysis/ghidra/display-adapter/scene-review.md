## Resolved blocker

`allocation_header` originally included a `uint64_t` union member, imposing8-byte alignment on RV32. Native TLSF at `0433cb96` rounds sizes to4 and splits at allocated-size+4; only4-byte returned alignment is proved. Host malloc and its test wrapper provided stronger alignment, masking this mismatch.

The current `scene_session.c:7` uses `{size_t bytes; unsigned kind;}` with a pointer-alignment static assertion. It remains8 bytes on RV32, now requires only4-byte alignment, and returning header+1 preserves the allocator's alignment. Core stored objects/workspaces inspected here use at most pointer alignment on RV32. The machine-test worker subsequently confirmed the final actual-RV32 scene-004 run exercises owned allocations at4 mod8; the correction is code-identical on RV32 while removing the C alignment violation. A plain host malloc replay alone would not exercise it.

## Ownership and callback findings

- `graphics.c:46` is the sole attached final destructor. It clears the magic, detaches/deletes the timer, disposes scene allocations, invalidates the image cache, then frees palette/pixels and owner. Scene release only stops pacing and frees its descriptors/store/workspaces; it does not separately free the aliased canvas. No duplicate canvas free was found.
- `tick` immediately returns after `image_delete`; no owner/timer dereference follows the deletion callback that frees both. The native timer self-delete contract was established earlier in this directory. Normal pumping keeps owner alive, invokes scene rendering synchronously, then flushes settled notifications.
- The scene session creates no native second timer: its timer handle1 is an internal sentinel. `timer_start` records time/period, and the existing20ms LVGL owner timer drives `pump`. It clears `timer_armed` before calling the core, allowing that core call to rearm once. Dispose clears the arm before freeing memory. No callback from this sentinel can arrive after owner destruction.
- `scene_present` ignores the supplied raster descriptor intentionally: all scene targets resolve to the owner's palette+64 raster, with600×350, stride300,105000 pixels bytes. Core `present` finishes deferred rendering before native `image_source` borrows the existing image descriptor/data. No temporary raster data pointer is handed to LVGL. This remains valid only under the documented fixed-owner-raster contract.
- Native image-source, cache invalidation, timer/object operations and scene dispatch execute on the display worker; the BT handler only copies a bounded job. The reviewed paths do not invoke an LVGL scheduler recursively or explicitly reenter scene dispatch. `P.send` may sleep/retry but the previously traced sender does not pump LVGL callbacks; holding `executed` across the send is consistent with display-task serialization. Hooks must retain their documented no-reentry/no-destroy contract; arbitrary replacement hooks that delete the owner during `present` would invalidate it.
- `mm_native_builtin_text` receives NULL through the owner wrapper, correctly selecting the native API under `MM_NATIVE_TEXT_FIRMWARE`. It never receives the owner pointer as a glyph API table.

## Queue, replies and notifications

The BT message bound is8192B. Initial validation checks supported mode and coarse framing; deeper validation deliberately happens on the display worker. Job and payload are copied before releasing the borrowed request TLVs; `post` copies the job synchronously and the local job is then freed. The native envelope remains stock-worker-owned and is freed after the gate returns. The display gate and original worker continuation ownership are unchanged.

The transient admission test is evaluated while the incoming request is already resident and reserves `32KiB + 2*(length+4) + 8`: local job plus queued envelope. The request is released before posting, which reduces actual overlapping storage. Native queue priorities can still silently drop a job, and queue allocation uses the stock asserting allocator. Correctly, enqueue produces no success acknowledgment; only execution responds. A missing response remains a timeout, not evidence of completion.

`cache_response` correctly sizes/copies its JSON text, calls the native copying JSON constructor, then frees the temporary string. Both command responses and settled notifications free their TLV lists after the native copying sender returns. Settled tags are buffered during core dispatch, so the correlated command response is sent first. A single unbundled SHOW/HIDE can report the superseded tag plus the new tag; the four-tag array covers the observed paths. No bundle mode is admitted. Timer notifications are flushed after each pump.

`o->event` is the **most recent nonempty executed command event**, not the original event that first introduced an animation tag. Thus a later PUT/SHOW can change the event used for an older tag's settled notification. The payload's tag is the stable scene correlation key. This is a protocol scope detail, not a memory defect; clients must not require the originating event for asynchronous tag settlement. Explicit clear/expiry/parent deletion frees the scene without promising delivery of all pending settled tags.

## Memory and stack limits

The170KiB session budget counts requested scene allocations plus the adapter's8-byte RV32 header. It excludes the owner, palette/canvas, native object/timer/event metadata, native allocator bookkeeping/rounding, incoming/queued data and reply allocations. The48KiB check reserves a snapshot of summed native free space while allocating scene storage. It is **not** an atomic reservation or largest-free-block guarantee; the lower try allocator still safely returns NULL on ordinary no-fit, and core failure paths release/roll back their owned allocations. The previous native LVGL create/event/timer allocation assertions remain possible despite total-free policy margins. Response/queue allocations also retain native OOM policy. No new global allocator bypass or critical-section extension was introduced.

The scene storage getter/canvas input are validated; `scene_session_init` accepts only initialized dimensions<=1024 and `mm_raster_validate`-valid memory. Production callers supply freshly zeroed owner storage and nonoverlapping hook/raster structures. The generic session API does not defend every contrived alias of `s`, hooks and raster, so its documented zero/unowned/nonreentrant caller contract matters. Production supplies these independently.

The final build's per-function stack evidence shows probe400B, display112B, session dispatch176B, pump32B and native text144B+helper48B. Native text's ordinary default glyph path adds the previously traced176B, or368B including its own adapter frames. All compiled individual frames remain below512B. Several of these frames coexist with core render/vector/LVGL calls; **512B is not a cumulative bound**. The proved task allocations are display8192B and app/BT4096B. Compilation/static frames and host tests alone do not prove worst-case interrupt/log/error depth or task high-water margin. Actual-RV32 execution tests should retain stack/callee-save checks and representative expensive vector/scene paths.

`pump` uses wrap-safe unsigned elapsed ticks. The stock tick is configured1ms. The20ms owner timer quantizes scene periods (e.g. a33ms period may become40ms between idle pumps); rendering and response sending add latency. Frames do not accumulate in a second queue and animation positions use elapsed time, but no hard render duration,30Hz cadence or one-second lease-expiry deadline under a busy worker is proven. Keepalive extends the owner's one-second lease without taking over its retained scene; normal UI/parent changes and timeout delete the owner at the next owner timer opportunity.

## Text and parity scope

`builtinText:true` means the resource-backed native adapter is linked, not that every Unicode scalar or G2 font pixel is supported. Default native height34 differs from G2's20; only the three proved mapped font handles are accepted. The font resource partition was not included in OTA, so repertoire is unknown. Unresolved/dynamic-cache/unsupported glyphs make the adapter reject the entire string before its own pixel writes.

The portable `mm_scene_shape_draw` currently ignores the builtin-text callback return. A retained command can therefore report applied, render its background/other objects, and omit unsupported text. Callback preflight protects that string's raster mutation, not transaction-wide successful text rendering. This is an explicit capability limitation and should remain visible in scope/testing; it is not proof of full text parity. Native callback wrappers can touch the existing dynamic fallback cache while searching before their result is rejected, though no cache bitmap is fetched/retained. Existing display-worker serialization remains required.

This reviewer did not rerun unchanged broad suites or touch the device.

These executed-path measurements improve the compilation-only evidence without turning it into a full native task-stack proof.
