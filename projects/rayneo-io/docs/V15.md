# CFW v15: cached fonts, link loss, clipped inline text, lighter frames

`GLASSLYCFW-IO/15` uses the same pinned Strix OS 1.0.4.12 base and the same
hook sites as v14; only the appended module changed. It is built and
host-tested, not flashed or hardware-validated.

## Fixes

- **Cached-font text drew from the builtin font.** A font asset is
  `[96 x u32 offsets][glyph images]` with the glyphs back to back. Each glyph
  was decoded with every byte to the end of the asset, the decoder did not
  stop at the glyph's last pixel and parsed the next glyph's `[w][h]` as a run,
  which overran the image. Every glyph but the asset's last failed:
  TEXT_CACHED fell back to the builtin font and mode-20 DRAW_STRING with a font
  asset NACKed. A glyph is now decoded from its own length (`asset_image_bytes`).
- **Images and glyphs no longer decode through the store.** Each blit took a
  transient `w*h/2` scratch from the asset store, so with the store full the
  image was skipped while SHOW still replied APPLIED. The RLE is now decoded
  in one pass straight into the clipped canvas through the LUT: no scratch,
  no granule-bitmap scan, no zeroing and no second pass. A stream must be
  exactly one image; stored assets are validated when they complete, so
  nothing is half drawn.
- **Phone link loss.** The page kept the panel until its 120 s lease ran out
  after the phone went away, and a wake then reopened the stale scene for
  another lease. The page tick now watches the launcher's `LinkMonitor`
  connection state (`cfw_link_up`, launcher.c): once it has read up since the
  session's QUERY, a down closes the page (PAGE reason 5, dropped with the rest
  of the uplink queue, which belongs to the lost connection), clears `queried`
  (no gesture, head or ANCS relay), the wake takeover and the compass. The
  wake takeover and the slept-lease renewal also require the link to be up.
- **PAGE_OPEN on an open page** renews the lease and replies `PAGE [1][0]`
  instead of re-running the launcher-idle gate, which could answer busy.
- **BUNDLE presented mid-packet.** A bundle cleared the packet's presentation
  hold and presented between the two eyes' records; it now restores the hold
  it found and presents only when there was none.
- **TEXT_INLINE ignored its box.** The phone sends `[x][y][clipW][clipH]`;
  glyph pixels now clip at `x + clipW` and `y + clipH` where those are > 0, the
  canvas otherwise, never on the left or top (the G2's `shapes.c` rule), in the
  scene and in mode-36 records.
- **Uplink.** The queue holds 15 replies (16 slots; the context grows from
  80,312 to 81,856 B);
  a full queue is drained before anything is dropped and the ANCS relay drains
  it before giving up on a notification. The page tick flushes again at its
  end, so gestures, SETTLED and lease replies leave in the tick that queued
  them instead of the next one.
- An empty TEXT_INLINE no longer leaks a 64-byte store granule.

## Performance

- A PUT invalidates a lens's static-layer cache and other-eye copy only when
  it journals for that lens (a definition, a completed or evicted asset);
  chunks of an upload in progress invalidate nothing.
- Presents rewrite only the 220 canvas rows' pixels. The margins (the
  parallax shift reads into them) and rows 220..279 of both eye buffers, about
  50 KB, are zeroed when the page takes the panel, on wake and after a probe
  pattern (`disp_clear`) instead of on every present.
- Path and rotated-shape fills keep an active edge list: edges are sorted by
  top once and a pixel row tests only the edges that span it, instead of every
  edge at every sub-row. Output is unchanged (see Validation). The vector
  workspace, allocated on the first path or rotation, grows from 10,752 to
  13,312 B.

## What "link down" means here

`LinkMonitor` byte `+6` is written by `notifyConnectionChange`, whose one
direct caller, `LauncherThreadMsgHandler::handleConnectionChange`
(`0x106EAEA8`), passes `state == 1` from the connection-change message; the
same byte backs `LinkMonitor::isConnected` when the interface query fails
(disassembly of 1.0.4.12). It is the connection, not the bond. A link that
dozes while the glasses sleep (no keepalives arrive, the page timer does not
run) is still connected and keeps the wake takeover. If the BLE link
itself drops during sleep, the first tick after wake sees it down and closes
the page; the scene comes back when the phone reconnects and opens the page,
not at wake. Whether sleep ever drops the connection is not verified on
hardware.

The connection message reaches the launcher through its message queue, so a
reconnect's QUERY could be handled while byte `+6` still holds the previous
disconnect. Link loss is therefore acted on only after the link has read up
since the session's QUERY.

## Validation

- Firmware cross-build, 76 symbols resolved by name and verified, every hook
  site byte-checked, patch replay/reproduction (clang reproduces the committed
  patch set) and OTA integrity checks pass. Module 79,048 B; patched AP
  9,545,616 B (ceiling 9,600,000). `hooks.json` was resynced from
  `cfw_patches.json`; v14 left v13's module offsets in its existing `new` bytes.
- Host suites (cache, compass, head, image, memory, raster, session, vector)
  under ASan/UBSan and the Python protocol tests pass. New coverage: a
  two-glyph font drawn from its first glyph (scene and mode 20), image blits
  with every store granule taken, exact-length streams, canvas and box
  clipping, TEXT_INLINE boxes with zero/negative sizes, a bundle inside a
  packet, scene serials across upload chunks, the empty TEXT_INLINE leak, and
  a new session suite (page.c, link.c, ident.c on a fake link monitor): link
  loss, a reconnect's early QUERY, a dozing link past a slept lease, the
  takeover and renewal without the link, PAGE_OPEN renewal, the end-of-tick
  flush and a full uplink ring. The vector suite adds 400 random fills
  (contours and edge soups, both winding rules, coarse grids for equal
  crossings) compared byte for byte with the previous all-edges scan.
- The compose change was compared against the v14 compose on host buffers
  (stock frame, page open, probe pattern, one-canvas fallback): identical.

Hardware validation is pending. Flash v15 and run `tools/suite`. Then:

1. With the page open, turn the phone's Bluetooth off: the page closes at
   once and the disconnected view shows (not after 120 s). Turn it back on:
   the app reconnects and raises its frame. Background the app and let the
   glasses sleep past the lease: on wake the retained scene still shows.
2. Text that overflows its element box is clipped at the box. Check single
   lines in boxes shorter than the 25 px line pitch: the phone sends
   `clipH = h - 2`, so their glyphs are cut there, as on the G2.
3. A cached font (TEXT_CACHED, mode 20) draws every glyph from the font.
4. `bun anim-timing.ts` and `bun scene-timing.ts`: compose time per present
   should drop; SETTLED and gestures should not wait an extra page tick.
5. With depth set, the margins stay black; DISPLAY_PROBE 6 then 7 returns to
   a clean scene.
