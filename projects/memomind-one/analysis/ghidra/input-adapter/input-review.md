# Passive input implementation review

Read-only review of `runtime/graphics/input.c/.h`, conditional integration in `graphics.c`, helpers in `native.c`, and observer gate in `entry.S`. [Source hashes](input-review-snapshot.json) pin the reviewed snapshot. No firmware/device changes or independent live tests were performed by this reviewer.

No concrete ownership/native-ABI blocker was found in this snapshot. This is a source/evidence review, not a statement that hardware input parity or recovery has been proven. The host/machine test owners retain responsibility for the final compiled artifact and test results.

* The hidden image is created under the current LVGL screen and hidden immediately before yielding; it has no source or pixel allocation. The proven direct `obj_add_flag(image,1)` ABI is used. Hidden objects remain discoverable children and remain subject to ancestor deletion. Invalidation/layout changes are possible and are acknowledged in the source.
* The delete callback retrieves its own registered userdata, clears magic, detaches/deletes its timer and frees the owner. The timer callback deletes the image on expiration/screen change and returns immediately; it does not access the freed owner afterward. Registration failure deletes the image before freeing the unregistered owner. Timer-creation failure deletes the already registered image, letting the delete callback own cleanup. This is consistent with the previously proved native delete/timer self-delete contracts.
* All owner discovery and mutation happen on the display worker. The BT handler validates/copies a bounded job, releases request TLVs, queues a copied envelope and frees its temporary job. It does not retain the incoming TLV or event pointer. Queue failure produces timeout rather than an immediate success claim. Display completion sends a correlated event via service15/command0x7c and then releases caller-owned response TLVs, matching the established native sender contract.
* The observer filters zero-payload class2/class3 events, looks up the callback-tagged owner, checks the lease and only copies scalar fields into its fixed32-record ring. It does not create/delete objects, allocate, send, wait, alter settings, or enable sensors. Its call chain is screen/default-display lookup, child/event-descriptor scan and tick read; none of the reviewed native helpers introduces a plugin lifecycle guard or borrowed callback lifetime. The child scan is linear in existing screen children/event descriptors, so it is not a constant-time lookup or a proven fixed CPU deadline.
* Overflow drops the oldest retained record and saturates the drop counter. Sequence exhaustion stops insertion and flags exhausted rather than wrapping; delivery cannot silently reuse sequence numbers. Poll removes only acknowledged records, retains unacknowledged records, and returns at most eight at a time. A caller acknowledging unseen records can intentionally discard them; this is the explicit protocol's responsibility, not an inferred server guarantee of delivery.
* Nonce/mask conflict checks keep accidental replacement separate from renewal. An expired owner is deleted before command execution; expired observation does not renew or delete it. Screen replacement is handled by timer cleanup and ancestor lifetime. On-screen stock app changes that reuse the same LVGL screen do not end a session: the observer intentionally remains a passive screen-scoped listener, not a launcher-only input consumer.
* The assembly gate saves/restores volatile integer/FPR state and fcsr around the observer, then tail-forwards the unchanged envelope to stock dispatch. Its 144-byte frame is removed before stock processing. The FP legality prerequisite is supported by [fpu-context.md](fpu-context.md). Final machine tests must continue to check preservation on each admitted and skipped branch.

Remaining limitations: native LVGL object/event/timer/JSON allocations may assert on OOM despite nullable C interfaces. The free-byte thresholds are conservative snapshots, not atomic allocation reservations or fragmentation guarantees. Creation and polling still have native allocation/sender work outside the observer. Owner lookup cost depends on stock UI structure; cumulative callback/interrupt stack and task high-water margin are not established by individual compiler frames. Polling/lease expires if the client stops renewing; the protocol supplies historical ticks, not real-time pushed input. Native cooked events can have multiple origins and be consumed later by stock routing. Neither raw ring provenance nor G2 wake takeover/head-up settings behavior follows from this observer.
