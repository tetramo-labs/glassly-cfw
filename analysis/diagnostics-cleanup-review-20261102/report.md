No device, runtime or test edits. `source-pins.json` records the inspected sources. This is an implementation contract and gap assessment, not a completed native feature claim.

## Exact mode7

`patches/zlib_glue.c:492–520` masks mode with0x7f before this branch:07 and87 are identical. Payload `[mode][sub]`; missing sub becomes0xff, unknown sub succeeds without effects, trailing bytes are ignored. No bundle admission (mode8's allowlist excludes7/87), immediate presentation, or scene takeover. Even missing/unknown sub calls `getCustomCfwContext`, which may create the singleton; allocation failure still yields branch success. Canonical encoders should emit07 followed by0/1/2.

| Subcommand | Effects |
|---|---|
|0 clear|Zero reorder/skip/duplicate flags, sticky allocator flag, diag_seen/fid_resync, last/high FID, NACK count/reason, worker-failure count/mode, allocation-failure count/bytes/heap, gate-timeout count; fill16-entry recent FID ring withffff and reset cursor.|
|1 hide|Set diag_hide1. No redraw.|
|2 show|Set diag_hide0. No redraw.|

Clear does not reset visibility, previous worker/present times, cycle calibration or message probe. Receipt itself publishes latest message size/CRC before dispatch and the outer worker later replaces timing, so 'not cleared' does not mean those values stay constant throughout a request. Actual singleton initialization in `cfw_context.c:39` hides the overlay by default despite stale context-header comments.

Frame IDs are **uint16**, not32. `debug.c:86–111` sets diag_seen on frame admission. Keyframe sets fid_resync1 and returns without clearing recent IDs. Delta scans all16 slots first; a duplicate sets f_dup and returns without changing last/high/ring/resync. Otherwise uint16 subtraction from last gives reorder when d==0 or d>8000, skip when d>1 (thus exactly8000 is skip), unless resync suppresses comparison. It then clears resync, updates last, updates numeric maximum high, and advances the ring. Sentinelffff means an initialffff is classified duplicate. This is exact upstream behavior, not a suggested bug fix. The flags never suppress execution of a frame.

FID location is5..6 for03,9..10 for83. Upstream records keyframe before allocation/RLE validation and delta after bbox validation but before shadow/RLE validation (`zlib_glue.c:672,722`). Memo's safer validate-before-mutation raster adapter currently ignores FIDs. Record timing on invalid frames must be explicitly selected/documented if changed; do not silently call exact-counter parity.

NACK/worker counts are uint16 and increment naturally; allocation count is uint32. Upstream NACK reasons describe its private transport: flags/context/inflate/CRC/handler. GM command refusals, GM checksum errors and private transport NACKs are different producers. Do not report a permanently zero unobserved counter as a measured success. `message_probe` is one aligned32-bit snapshot containing size16+CRC16, not a32-bit FID. Producers are `cfw_message_received`, `message_transport.c` and `malloc.c`, not the overlay alone.

## Reusable diagnostics renderer and the important separation

`draw.c` supplies the portable Terminus6x12 font:95 printable ASCII glyphs,1140 read-only bytes, one byte per row, top6 bits MSB first. `set_pixel4`, `draw_glyph`, `draw_string` clip to tightly packed width/height; high nibble is left. Nonprintable chars draw nothing but still advance6; strings are NUL-terminated and intended to be bounded internally. Optional background paints a one-pixel padded box. The pure table/pixel code can be extracted unchanged with upstream source pin preserved and tested independently from native font APIs. It does not need mode15/native resource fonts.

`debug.c:153` composes four lines at offsets2/14/26/38: flags plus prior worker/present microseconds; received size/CRC; per-G2-heap free/max KiB; NACK/handler/allocation/gate counters. ARM DWT addresses/calibration and the three G2 TLSF heap addresses are hardware-specific and must not be copied. Memo has a proved millisecond tick042d02c6 and free/low-water getters0433c460/0433c4a4; low-water is not largest allocation. Do not label milliseconds as microseconds, invent G2 heap labels, or call an unavailable metric zero. Native error/logging and allocator failure paths remain separately bounded.

**Overlay must not mutate clean scene pixels.** G2 `display_copy_hook` (`zlib_glue.c:945–947`) copies source shadow to physical output, then paints diagnostics into output only. It forces top rows into dirty copies while visible. Memo's image descriptor currently borrows the same editable canvas used by retained scenes, delta and rectangle-copy. Painting diagnostics there bakes text into future operations and hide cannot restore the original background. A separate owned small LVGL image layer is a feasible architectural direction using the existing descriptor/delete evidence; its lifecycle, ordering, source/caching and dimensions still need implementation/tests. Mode7 hide/show itself must defer visual change to the next actual presentation to preserve 'no display change'; immediately applying LVGL HIDDEN invalidates now and differs. Never expose diagnostics over stock calls/notifications once custom ownership ends.

## Exact mode11 and current Memo gap

`zlib_glue.c:577–581,829–891`:0b/8b succeeds with any trailing reserved bytes, no minimum beyond mode byte. No nested bundle admission. No existing singleton→success without creating one. Under the display gate it first clears direct lease/ownership/pending pointers; releases scene/assets (advancing cache epoch), releases shadow, stops/deletes scene timer, suppresses tone-sequence callbacks before stopping/deleting its timer and resets buzzer. A delete failure keeps the timer handle for retry. It cleans ANCS/ALS/BLE session ownership, disables owned compass forwarding, clears wake lease/pending/nonce and retries wake-timer deletion. If a dashboard launch was pending, it starts dashboard after cleanup. Diagnostics are hidden but sticky history retained; singleton and transport streams remain. Microphone array is explicitly **not** stopped: it owns a separate90-second lease/STOP command. Other independent workers must likewise not be freed speculatively.

Current `runtime/graphics/graphics.c` admits onlyexact[0b], rejecting8b/trailing, then deletes the graphics image on display worker. Its synchronous DELETE callback clears magic, detaches/deletes timer, disposes scene/core allocations, invalidates image cache, frees palette/pixels, then owner. Subsequent repeat clear succeeds without owner. The request envelope remains stock-worker-owned; no pointer to deleted owner is used for settled flushing because executed is null on the clear branch. This safely cleans implemented graphics resources and restores stock UI through removal, but is not all G2 controller cleanup.

There is an independently owned input subscription in `input.c`, keyed by its distinct deletion callback, with a hidden source-less LVGL child/timer and32-record ring. Current mode11 leaves it alone. A future full implemented-session cleanup can delete that opt-in subscription through an input-module helper on display worker, preserving the passive hook and stock button forwarding; this is an explicit Memo extension, not a copied G2 callback. Do not cast input and graphics owners interchangeably. If intentionally preserving input across display clears, document that separate-session policy instead. Button support itself remains required.

Current scene epoch exists inside the graphics owner; deleting it loses epoch history before a new owner is created. G2 singleton persists the incremented epoch across cleanup. Likewise diagnostics inside graphics owner cannot retain sticky history across mode11. Any durable state needs an explicitly owned/versioned persistent context, with initialization, publication, cleanup and reset rules. Existing256-byte canary registry is a separate fixed ABI; do not assume unused bytes are a free new slot without reviewed nonoverlap and constructor/version gates.

Mode11 must not free/cancel active flash canary worker/context, reset storage mappings, erase data, reset native application resources or disable shared stock sensors. Prior `analysis/ghidra/input-settings/report.md` shows raw IMU/general enable APIs modify shared activity bits, not caller-specific leases. A saved Boolean and later restore can overwrite another native owner's change. Compass/raw IMU remain required future work; no safe owned teardown is established merely by their API addresses. ANCS/action/ALS/buzzer/generic wake native cleanup remains pending until those adapters own actual resources. Gesture/ring/keyboard exclusions do not remove compass/ALS obligations.
