# Resource-backed text implementation review

Files added only: `runtime/graphics/native_text.h`, `native_text.c`, `tests/test_native_text.c`, and `tests/run_native_text_tests.py`. No graphics owner, compiler, active image, device or flash changes.

The entry is the exact scene callback signature `mm_native_builtin_text(user,raster,payload,length,dirty,tokens,capacity)`. `user` is an injected `const mm_native_text_api *`; it is **not** the graphics owner. Compiling with `MM_NATIVE_TEXT_FIRMWARE` enables a readonly native table and selects it for `user=NULL`. An owner-aware scene callback must wrap this call with NULL/native API explicitly. Host builds contain no firmware-address callbacks.

Only default0438f77c, large0438f75c and emoji04385e7c resource-backed fonts are accepted. Native binding uses descriptor wrapper042d153c and bitmap wrapper042d14be; it reads height/baseline/flags only for those three addresses. The ready callback reads proved initialized byte0205a048 and rejects cold resource initialization. Missing/unresolved glyphs and the dynamic cachefont0200fb44 reject the entire string during preflight; this deliberately differs from upstream G2's missing-glyph advance-only behavior. The stock descriptor wrapper can traverse/touch the existing dynamic fallback before returning it; the adapter rejects that result without fetching/retaining its bitmap. No mutation of font objects, cache management calls, free/release or allocations are introduced.

Callbacks/resources/input must be deterministic and stable for the entire synchronous call. The adapter performs full strict-UTF8 decoding, then all-glyph preflight, then a second lookup pass while drawing. This avoids retaining128 descriptors/pointers on the display stack. Preflight failures leave target pixels and dirty rectangles unchanged; token scratch may change. A provider that changes results between the two passes violates the API contract and is not given transactional rollback. Existing display serialization/lease admission remains the caller's responsibility.

The adapter validates the raster and aliases, text length<=128, token capacity, mapped-font handle, metric bounds, subpixel/placeholder flags, exact resource1/2bpp and requested bitmap extent<=1000B. Bitmap payload readability for ceil(width*height*bpp/8) is a borrowed-resource contract. The native c6 font bytes were absent from OTA; their exact coverage and the native callback's odd last-record size fallback remain the static investigation limits documented in ../report.md. Do not claim those data have been independently validated or that native fonts match G2 20px pixels.

Tests passed with ASan+UBSan and warnings-as-errors, evidence `analysis/evidence/native-text-host-001/report.json`. Cases include all64 intensity/inverse/transparency combinations, 1/2bpp continuous MSB-first rows, odd-width framebuffer padding, negative and offscreen placements, fallback baseline, inline controls and next-glyph forwarding, valid and malformed UTF8, unresolved/dynamic/unsupported glyph rejection, multiglyph failed preflight with pixels+dirty unchanged, zero-area glyphs, zero/limited token capacity, aliases, exact message length,128-byte limit and dirty-list saturation.

RV32 compilation uses the exact `scripts/compile_memomind_graphics.py` FLAGS at review time; `build.json` records command+source hash. Executable sections total2272B, readonly API24B, data/bss0B. Sole external undefined reference: `mm_raster_validate`. `native_text.su` shows main144B, glyph helper48B, native binding wrappers0B. Deepest adapter stack192B; plus previously proved successful default native metrics176B gives368B excluding graphics/scene caller frames. This is not an interrupt/logging/error-path bound. Actual linked integration must retain its existing whole-runtime frame/call-chain gates.
